## Path 3 — Tournament-entry histories: candidate, not implementation

### Information boundary and scientific question

For event `e`, define one common cutoff `C_e` before its earliest actual play. Freeze **all** players' ratings, Four Factors histories, opponent adjustments, shrinkage, ranking context and fitted transformations using only information admissible at `C_e`. Earlier-round results from the same event must not enter later-round predictions. A player's first appearance is not an interchangeable cutoff: other players may already have played. Late entrants need the same historical cutoff and a prespecified cold-start rule. Later-round forecasts would be conditional on the eventual pairing, using frozen histories; this is not a claim that the full bracket was known at entry. Advancement cannot become an unacknowledged feature.

This prevents within-event result leakage **only if the entire feature pipeline is frozen**. It does not solve cross-event leakage or prove that a retrospectively corrected source reflects what was knowable then. `tourney_date` remains an event grouping/boundary label, never an actual match date. Retirements, partial retirement statistics and walkovers remain excluded from primary histories, Elo updates and evaluation; their audit records remain intact.

Match-sequential forecasting asks how well current pre-match knowledge predicts the next match. Event-entry forecasting asks how well knowledge fixed before the event predicts its matches. Both concern calibration and interpretation, but the available information and estimand differ. A frozen-Elo win is not evidence of beating standard match-sequential surface Elo.

### Evidence still needed

For each event, establish a time basis/timezone, an evidence-backed lower bound on actual first play, and an upper bound on final completion **and** availability of each included result/statistic version. The cutoff must demonstrably precede play. A published schedule may help define it only with evidence it was available then and precedes actual play; scheduled end is not a completion bound. A later downloaded final score proves neither historical publication time nor when a corrected count became available.

Let `A_j` be a supported upper bound on completion and availability for all retained inputs from earlier event `j`. Require `A_j < C_e`; equality or overlapping uncertainty intervals fail closed. Document source/version, boundary meaning, publication/revision evidence and uncertainty. Unknown availability cannot be cured by adding an arbitrary lag. An assumed publication delay would be an explicit, unverified methodological assumption requiring separate approval and sensitivity assessment, not verified historical availability.

Overlapping events need a dependency/release graph, not sorting by event start, filename, round number or CSV position. If a player's previous event has not safely released before the next cutoff, exclude that whole batch, even if the player exited early. This intentionally sacrifices recent information; player-specific partial release would be a different design. Adjacent/consecutive events use the same strict test. An event delayed beyond its planned end cannot release on schedule. Apply the same evidence rule to ATP and WTA, with tour/event-specific calendars, formats and missingness; that does not justify identical Elo parameters.

Compare evidence-triggered release with an additional one-event, seven-day or longer lag only after boundaries are supported. One event is not a fixed duration; a week cannot guarantee safety across overlapping or extended tournaments. Additional delay may discard useful information without fixing missing evidence. No lag or numerical cutoff is selected here.

### Elo and factor updates after release

A candidate could replay eligible matches after batch release using validated player-relative dependencies, while keeping the event's forecast snapshots frozen. Each Elo match update uses the contemporaneous latent ratings of both players; union their dependency chains and validate a topological order. Overall and relevant surface states update under a fixed rule; the prediction uses the pre-event overall/surface blend. This separates delayed learning from frozen forecasts, and requires explicit validation/approval before implementation.

Late releases must not simply append an older shared-player match after a newer one. The specification must choose whether to withhold dependent updates or rebuild the current eligible state in validated dependency order; any rebuild must preserve already issued forecast snapshots. Cyclic, missing or contradictory dependencies block the affected result. Release order is not automatically play order, and neither solution is adopted here.

For simple fixed-parameter Elo whose updates touch only the two players' overall/surface states, disjoint-player updates commute. Shared-player updates generally do not. Global match-count-dependent K, pool normalization, adaptive hyperparameters or shared elapsed-time decay can invalidate commutation. Bracket evidence may establish shared-player order locally but does not prove cross-event releases. Computing every residual from frozen ratings and summing them would be a different, permutation-invariant batch-rating algorithm; it is not standard Elo and is not selected.

Exact **last-K** histories still require each player's match order across and within eligible prior events, particularly when K cuts through a batch. Entire-batch aggregates cannot silently stand in for last-K matches. Excluded RET/WO must not occupy eligible-history slots; any ordering dependencies they explain remain audit evidence. K, minimum sample size and warm-up coverage are unselected.

Calendar windows and inactivity remain blocked without reliable dates. Assigning every match the event-end/release date changes elapsed-time weights and cannot measure actual inactivity. Date intervals may support conservative exclusion, not invented instants. The relevant last-activity definition, including how excluded statuses affect it, would need a separate rule. Deferring calendar decay allows a smaller candidate, not permission to implement last-K now.

Required future tests: cutoff before first play; input completion/availability strictly before cutoff; missing/equal/overlapping boundaries reject; delayed/revised publications and out-of-order releases cannot rewrite past forecasts; within-event snapshot invariant to earlier-round outcomes; post-cutoff future perturbations cannot change prior forecasts; overlap/consecutive-event fixtures; late-entry and cold-start behavior; per-player last-K order, cross-batch K truncation and RET/WO exclusion; disjoint-update permutation invariance and shared-player order dependence; surface/overall state isolation; outcome-neutral player-swap symmetry; no 2025 access or tuning. These are proposed tests, not executed model tests.

### Information loss, fairness and role

Later rounds lose all newly learned same-event form, opponent strength and point performance; conservative release can also omit recent prior-event matches. The amount and effect are **not measured**. Full matched-sample comparisons must report exclusions, available-history volume and round-dependent losses. Freeze official rankings, Elo and Four Factors at the same cutoff, with comparable warm-up scope, eligible outcomes and training/validation rules. Calibration/Brier/log-loss uncertainty remains tour-specific under the standing design. Equal cutoffs make a fair event-entry comparison, but information loss can affect the model families differently and may weaken Elo disproportionately.

**Recommended role, unapproved:** retain match-sequential surface Elo/Four Factors as the intended primary comparison. Develop event-entry only as a bounded **development fallback candidate**, then use it as a timing sensitivity analysis if sequential evidence becomes sufficient. If it is the only feasible route, making event-entry primary requires an explicit research-question/protocol amendment before validation/model selection and before opening 2025. Do not mix forecast cutoffs across models or label a fallback as the original benchmark. No forecast, operational batching, parameter or lag is implemented here.

## Path 4 — Remain blocked

Continue only separately authorized offline work: formula/denominator reasoning, analytic redundancy and interpretability review, synthetic algebraic examples, documentation consistency, and a saved-evidence inventory of timing/rights gaps. Factor research can compare candidate definitions without estimating weights, running historical predictors or producing forecasts. A broader inventory can catalogue already saved sources, URLs and missing evidence; it cannot discover live links or acquire material. Canonical histories, time-window features, Elo, fitted Four Factors and evaluation remain blocked.

Waiting preserves the intended sequential question and avoids unsupported assumptions, but supplies no estimated date of resolution. Repeated infrastructure work has opportunity cost: it postpones testing whether candidate factors are distinct and useful. Bound the next feasibility exercise and require an explicit go/revise/stop decision; do not automatically extend the acquisition ladder. Challenger work remains deferred until flagship infrastructure is validated; portfolio publication remains outside scope.
